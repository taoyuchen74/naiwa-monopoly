# 本机四槽存档

设置中的“管理4个存档槽”与游戏侧栏的“存档槽”打开同一面板。提供1个自动槽和3个手动槽，每个展示地图、轮数、人数、更新时间，以及真人角色、现金、地产数和当前行动摘要。空槽可直接保存，覆盖、读取、删除、导入需要确认；取消不写入。每个槽均可单独导入、导出JSON。

## 数据结构

| 槽位 | localStorage键 |
| --- | --- |
| 自动 | `naiwa-monopoly-v2`（沿用原键） |
| 手动1 | `naiwa-monopoly-v2-manual1` |
| 手动2 | `naiwa-monopoly-v2-manual2` |
| 手动3 | `naiwa-monopoly-v2-manual3` |

记录保留原来的扁平JSON结构：`{schemaVersion:1,savedAt:毫秒时间戳,...原规则状态}`。`schemaVersion`描述存储格式；原有`version:2`、`rules:7`继续表达游戏规则版本，地图、玩家、阶段、随机状态等字段含义不变。恢复后的规则状态不包含`schemaVersion`。

`naiwa-monopoly-v2-backup`继续作为覆盖前自动存档的独立撤销备份，不是第五个用户槽。新开局、从手动槽读取、向自动槽导入时先保存原自动槽的完整字节；读取自动槽本身不覆盖这份备份。手动槽操作互不影响。删除自动槽后，下一次游戏动作会重新自动保存，面板会明确提示。

## 迁移和存储边界

`dist/save-schema.js`集中提供纯函数`migrateSave`及`encodeSave`。无`schemaVersion`的旧JSON走原有迁移、校验流程，包括豆奶迁移为奶茶、地图和配置默认值、股票组合迁移等。读取、列举不会改写旧字节；下一次保存或导出才生成格式1。旧存档缺少时间时显示“未知（旧存档）”。

格式1必须具有有效保存时间。损坏数据、未知格式版本拒绝读取或导入，原字节保留；面板仍允许将不兼容/损坏槽导出为原始数据，再由用户明确确认覆盖或删除。JSON导入不绕过规则校验。

`dist/save-repository.js`接收Storage兼容对象或延迟取得它的函数，可注入时钟；封装四槽读取、保存、删除、序列化、导入解析和自动槽备份。引擎原公开存档助手委托给它，界面不直接操作游戏存档键。偏好设置和开局配置仍使用各自原有键。

确认流程记录当时的原始字节，落盘前再比较；确认期间槽位变化会拒绝操作。备份失败时不覆盖自动槽，存储写入失败时不替换当前内存游戏。localStorage只保证单键写入的原子性，多键备份和跨标签页操作不是数据库事务，比较检查不能保证同时写入的跨标签页互斥。
