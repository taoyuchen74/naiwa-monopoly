# 移动端布局与交互验证

延续奶油纸色、金色边框及 KuaiLe 角色标题；关键正文与面板说明按 14px 排版，输入控件 16px，常用按钮至少 44×44px。

## 布局

- 读取 top/right/bottom/left 四向 `safe-area-inset`。手动顺时针旋转时，将物理安全区映射到游戏的逻辑四边；主地图、顶栏、底栏、面板、通知和自定义下拉列表均留出安全区。
- 横屏把玩家资产列表和地图工具留在左侧，玩家列表与工具栏可各自滚动；右侧面板拥有独立滚动区。掷骰、结束回合和卡包保留在底栏。
- 竖屏将玩家资产改为可展开／收起的底部抽屉，面板也可收起。底栏明确分为回合操作、经营入口两行，避免自动排布挤出按钮。
- 页面根层锁定，面板和选项列表以 `overscroll-behavior:contain` 隔离滚动；地图继续使用原生 Pointer Events 单指拖动、双指缩放和取消捕获逻辑。旋转、失焦或隐藏时取消旧手势。
- 根据 VisualViewport 的可见大小和偏移放置游戏根层。编辑输入时保留原布局方向，避免软键盘改变宽高比后误切横屏；输入字号避免 iOS 默认放大。系统全屏和方向锁被拒绝时，CSS 手动旋转仍可工作。

## 可复现的浏览器测试

安装依赖并准备 Chromium：`npm ci`，`npx playwright install chromium`。

运行 `npm run test:mobile`。配置会构建网站、启动本地测试服务器，并逐一运行 360×800、390×844、844×390、768×1024 和 1440×900 五组视口。失败时保留交互 trace 和截图，路径为 `test-results/mobile/`。

每组执行真实页面操作：六人开局、卡包选择控骰目标、掷骰与购地确认、结束回合；遍历地产、卡包、银行、股票、商店和玩家档案；检查按钮触控尺寸、点击命中及正文大小；展开／收起面板；原生 CDP 触屏拖动与双指缩放；手动旋转前后继续手势；在长面板底部滚轮及触屏滚动并核对页面和地图未跟随滚动。

安全区检查向四边注入不同的非零 inset 值，核对原方向、手动旋转方向及弹层边界。软键盘检查聚焦实际银行金额输入后，收缩 Chromium 可见视口至键盘占用后的大小，核对方向未误变、输入和确认仍可命中，并实际存入金额。这是浏览器视口与触屏模拟，不声称验证真实手机刘海硬件、系统输入法或 Safari 键盘行为。

纯逻辑及原有规则回归使用 `npm test`，包括安全区映射、VisualViewport 偏移、页面缩放与键盘区分、键盘布局保持、选项弹层边界、旧手势取消及完整对局。
