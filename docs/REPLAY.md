# 本地回放与战绩

设置与结算页进入“回放与本地战绩”，可播放/暂停、循环1—3倍速、按玩家回合前后跳转，或从当前回放位置继续。播放器使用独立Game，不改当前旅行；在原有单一UI节拍中推进，离开面板即停止推进，不增加播放计时器。以只读简洁地图展示位置、归属、建筑等级，并展示轮数、当前席位、骰子及公开净资产，不显示手牌或持仓股数。

“从这里继续”走已有导入自动槽确认流程，原自动槽先备份；取消不改当前旅行或增加分支记录。确认后分支使用新的录制ID，原完成战绩仍保留。新开局启用录制；从存档继续会验证本地历史，能找到相同状态时接回对应命令前缀。没有匹配记录的旧存档从当前存档开始录制，界面说明起点；不会虚构此前操作。导入到其他浏览器的普通游戏存档也如此，需要完整历史时请另行导出回放。

## 格式1

```json
{
  "formatVersion": 1,
  "rules": 10,
  "captureId": "本次录制的本机ID",
  "initial": {"version": 2, "rules": 10, "setupSeed": 17, "seed": 123, "mode": {}, "players": []},
  "initialHash": "sha256-v1:...",
  "commands": [
    {"command": {"type": "roll", "payload": {}, "playerId": 0, "sequence": 1, "revision": 0}, "stateHash": "sha256-v1:...", "cause": null, "chain": "..."}
  ],
  "finalHash": "sha256-v1:..."
}
```

示例initial省略了正常GameState字段；实际必须是完整可恢复状态。只存这一份初始快照，其中含地图、角色/席位/难度、模式、轮数、起始资产、setupSeed以及当前确定性随机状态seed。每条成功的外部命令记录载荷、玩家、顺序、前置revision、执行后哈希和可选破产原因；不逐帧、不逐命令保存完整状态。重复或非法命令不录制。AI通过原aiTurn命令重算，不降低决策精度。

链为SHA256(前链或initialHash + JSON.stringify(command) + stateHash + JSON.stringify(cause))。规则状态哈希复用原canonicalState/stateHash，排除表现options和savedAt。载入时先完整执行到末尾，验证每条命令是否合法、状态哈希、链、破产原因及finalHash，验证成功后才开放播放器。载入验证时顺便建立只含命令下标的运行时回合索引。跳转重新从初始快照执行命令前缀，不持久化帧状态。格式/规则版本不兼容明确报错；同规则号下若执行结果变更，哈希也会阻止错误播放。

兼容输入格式0：本次定义的无链简化格式，仍必须是同一规则版本10、包含逐命令状态哈希和finalHash。验证状态后补链和原因、升级为1；这不是宣称支持任意历史发行版。旧游戏存档通过原迁移器规范化后可作为新录制起点；不尝试把规则9的回放当规则10播放。

这些校验用于发现损坏和未一致更新的篡改，不是签名或竞技防作弊。掌握本机文件的人可以重新生成另一份合法命令流及校验值。

## 摘要与隐私

结算页提供中文只读摘要及复制按钮。内容包含地图、已完成/限制轮数、并列排名和每席现金/存款/地产/股票市值/交通工具/贷款/净资产，不包含手牌、股票股数或成交成本。剪贴板失败时可选中文本手动复制。

回放文件包含整桌初始状态和可推算私有信息的种子/命令，不是公开摘要。导出入口明确提醒含手牌、勿公开分享；无需网络、账号或服务端，不提供加密隔离。

## 本地累计统计

独立localStorage键naiwa-local-history-v1：matches保留最近更新的20份回放，scores独立保留累计结算元数据。空间不足时优先淘汰最旧回放，累计统计不随之删除；单份也无法保存时当前录制仍可手动导出，界面提示未保存。损坏或未来版本的本地历史不自动覆盖。

录制ID只用于本机去重，不参与规则RNG或stateHash。同一局多次保存/恢复只计一次；同种子重新开局及从回放分支是新局。角色使用率分母为已结算真人和AI席位总数；胜率分母为该角色出场次数，经典并列第一计胜，经营挑战按实际目标成功而非资产榜首计胜。平均轮数按出场局的实际结束轮数计算。破产原因由破产命令前的欠款标签提取，经回放重算验证，不依赖可能截断的历史日志。

明确标注“本地数据、非竞技认证”；统计可被本机编辑、清除，不能代表真人玩家总体或官方排行榜。此前缺少scores的本地格式1记录会从现有结算元数据迁移；没有历史文件就不凭空生成统计。

## 验证与体积

测试覆盖完整AI对局最终哈希、命令/顺序/链/初始快照/最终哈希篡改、格式0迁移、未来版本拒绝、旧存档接续、回合跳转、分支与去重、经营挑战胜率、空间淘汰及公开摘要。浏览器以390×844和844×390真实点击验证所有入口、复制和接续确认，未声称真机验证。

模块复用同一带版本的engine导入，避免在发布包重复打入引擎。原1MiB原始脚本预算保留；gzip预算从十进制300000调整为300KiB（307200字节，增加2.4%），保持明确上限，用于新增回放/验证界面；实际构建尺寸由build-info.json及测试报告记录。
